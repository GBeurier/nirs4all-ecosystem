  `nirs4all-datasets` clone has metadata/cards/manifests but no tracked
  `datasets/*/canonical/dataset.json` bytes.

## Integrated Fix

| Repo | Commit | Scope |
| --- | --- | --- |
| `nirs4all-io` | `2e5e2a5` | Generate deterministic schema-2.0 dataset leaves in the E2E test, canonicalize them through `nirs4all-datasets.bootstrap` + `organize`, then validate `NirsDataset -> nirs4all-io DatasetPackage` with numeric, metadata, split, manifest and payload assertions. |
| `nirs4all-ecosystem` | this batch | Pin `nirs4all-io` to `2e5e2a5` and record the CI fix plus the next E2E reinforcement lanes. |

The fix deliberately avoids a skip, xfail, or artificial fallback. It replaces
the accidental dependency on private/local canonical bytes with a deterministic
canonical fixture generated by the same public code path that `nirs4all-datasets`
uses to publish canonical datasets.

## Risks

- The deterministic `nirs4all-io` fixture proves the bridge and canonicalization
  path, but it is not a substitute for later Dataverse-hosted real reference
  datasets. Once canonical DOI assets exist, add a second retrieval test that
  fetches and verifies a published dataset.
- Do not replace the Dataverse retrieval model with GitHub Actions artifacts or
  release-asset canonical bundles unless the storage contract is deliberately
  changed. The current ecosystem contract expects DOI/version/file-id backed
  canonical bytes.
- The 10 ecosystem scenario definitions remain intentionally honest: current
  `hybrid` gaps should only be removed after the concrete proofs above land.
